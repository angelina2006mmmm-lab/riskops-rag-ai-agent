# План тестирования

## Позитивные сценарии

- Индекс содержит все пять документов, уникальные идентификаторы секций.
- `/search` по простоям и ESG находит соответствующие документы.
- `/assess` возвращает верный класс в точках границы: 29.99, 30, 119.9, 120, 20, 50.
- `/ask` в offline выдаёт ссылку на документ, расчёт и trace инструментов.
- `/multi-agent/brief` выполняет поиск, оценку и проверку источника тремя ролями.
- Логика обработки настоящего ответа LLM с `tool_calls` тестируется подставным HTTP/LLM клиентом, без расхода токенов.

## Негативные сценарии

- Пустой запрос; `top_k=99` → HTTP 422.
- Отрицательное или некорректное числовое значение → ошибка валидации.
- Неизвестный `indicator`, недопустимое имя инструмента `run_shell` → отказ.
- Попытка `mode=llm` без API-ключа → HTTP 400 с понятным сообщением.
- Агент ограничен 4 раундами инструментов во избежание бесконечного цикла.

## Какие проверки не проведены

- Нет внешней LLM с действительным ключом в тестовой среде: настоящий вызов API/стоимость/качество генерации отдельно не измерены.
- Не проводились нагрузочное тестирование, security pentest, обработка реальных персональных данных.
- Векторная модель Sentence Transformers не загружалась: это опциональная интеграция.

## Запуск

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m scripts.evaluate --k 3
```

CI: `.github/workflows/ci.yml` запускается на каждом push/PR.
