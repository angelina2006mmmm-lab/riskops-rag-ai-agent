# Подготовка к техническому собеседованию

**Что реализовано?** Прототип RAG по синтетической базе знаний: chunking Markdown по секциям, retrieval TF-IDF, цитаты документов, Python-инструмент оценки показателя, FastAPI и optional tool-calling через настоящую LLM.

**Чем TF-IDF отличается от embeddings?** TF-IDF использует статистику слов и плохо учитывает перефразирование. Embeddings кодируют тексты в плотные векторы и лучше подходят для семантической близости, но требуют дополнительной модели и вычислений.

**Почему результат нельзя назвать полноценным LLM-ответом без ключа?** В offline-режиме извлекается фрагмент источника и вычисляется детерминированный индикатор. Генерации языковой моделью нет. Полноценное tool calling реализовано как протокол и требует подключения внешнего API.

**Что такое tool calling?** Модель возвращает имя инструмента и JSON-аргументы; сервер валидирует их и вызывает только разрешённые функции; результат возвращается в историю сообщений перед финальным ответом.

**Что здесь "мультиагентного"?** Три роли — исследователь, аналитик, reviewer — имеют отдельные интерфейсы и последовательно передают результаты. Это демонстрация декомпозиции работы, но не автономные LLM-агенты. Для следующей версии можно добавить модель-исследователь и модель-критик с ограниченным циклом взаимодействия.

**Как избежать галлюцинаций?** Хранить точные source/id, давать модели только подтверждённые фрагменты, не позволять ей самостоятельно вычислять числовой риск, возвращать "нет данных" при отсутствии доказательств и оценивать groundedness отдельно от relevance.

**Как проверить качество RAG?** Разделить метрики retrieval (Recall@k, MRR) и генерации (faithfulness, ответ на вопрос, наличие ссылки); использовать фиксированный набор вопросов и ручную экспертную оценку. На 5 учебных вопросах Recall@3 = 1.00 — это не показатель качества в продакшене.

**Почему политики не инструкция агенту?** Текст Markdown — недоверенный источник; команды внутри должны трактоваться как данные. Система ограничивает доступные инструменты и не предоставляет выполнения shell-кода.

**Какие улучшения?** Векторная БД, embeddings, reranking, evaluation с отрицательными вопросами, trace стоимости и latency, защита PII, мониторинг и CI.

**Как указать в резюме после публикации?**
