# Experiment card — AI analyst chat-routing laboratory

The code in this directory is an **educational demonstration**. All text, labels, knowledge policies, dates and simulated request latencies are synthetic. There is no connection to SBOL, Sberbank internal systems, a real banking API or live customers.

## 1. Research question

Can a revised *prompt* improve classification of banking-support messages into
balance / card_block / transfer_status / loan_payment / other,
without increasing malformed JSON, abstentions or latency?

An earlier experiment compared **deterministic regex emulators**, NOT LLMs. Its reported macro F1 0.3245 versus 0.9167 is hand-authored fixture behavior, NOT proof of a prompt effect.

A new experiment, src/real_llm_eval.py, performs genuine generative inference:
- One public instruction-tuned pretrained checkpoint: Qwen/Qwen2.5-0.5B-Instruct.
- CPU greedy decoding, fixed torch seed 42; two different written prompt variants.
- Ten synthetic examples, two per class, identical between variants.
- Few-shot example texts in prompt B differ from the evaluated messages.
- Strict JSON response contract: invalid outputs are counted as abstentions (other).
- All original generated answers, labels, parse validity, and inference durations are stored in the GitHub Actions artifact.
- Report accuracy, macro F1, structured-output validity, abstention rate, p50/p95 latency and per-message errors; DO NOT suppress failures.
- This is *offline paired inference on a tiny, partly templated dataset*, **not** an online randomized A/B test or evidence of a causal production effect.

### How to run

    cd extensions/chat-ai-analytics
    pip install 'torch==2.5.1' 'transformers>=4.48,<4.58' 'accelerate>=1,<2'
    python -m src.real_llm_eval

Real-LLM workflow: [.github/workflows/chat-real-llm-eval.yml](../../../.github/workflows/chat-real-llm-eval.yml). CI attaches reports/real_llm_prompt_eval.json.

## 2. Measurable multi-specialist LangGraph workflow

The orchestrator uses *actual LangGraph StateGraph* with deterministic specialists. The specialists are **not separate generative LLMs or self-directed AI agents**:

    [router] --balance--------> [account specialist] --|
         \ --card_block-----> [card safety] -------|
          \ --transfer------> [transfer specialist] -> [evidence verifier] -> END
           \ --loan_payment-> [loan specialist] ---|
            \ --other-------> [safe abstention] ---|

Components do not execute banking actions. They return mock knowledge-base references like SYN-CARD-v1. Source verification checks exact allowed IDs. Plain-text injection patterns cause early blocking; adaptive attacks may bypass these simple rules.

Evaluation on all 100 labelled synthetic messages reports:
- top-level intent-routing success rate;
- correct specialist/tool selection rate;
- valid citation ID rate;
- abstention and blocked request rates;
- invalid tool calls (expected zero);
- p50/p95 local Python execution latency;
- case IDs and labels for errors (without raw chat bodies).

When the real model report is available, its **recorded B predictions** are replayed through the *same* LangGraph. This provides a downstream integration-quality measurement, but the replay itself is not a live agent calling Qwen.

### Run the agent suite

    python -m pip install -r requirements.txt 'langgraph>=0.6,<2'
    python -m pytest -q
    python -m src.agent_eval

Agent report: reports/multi_agent_quality.json (generated by CI).

## 3. SQL monitoring and instrumentation

The offline SQLite example has CTE, correlated subquery, REGEXP and running-window metrics for classification events. Latencies are **simulated** there, unlike real LLM inference timers and LangGraph wall time. Neither represents a production P95 SLA.

For a *future* genuine online experiment, randomize by anonymous chat session, pre-register sample size and primary metric, guard privacy and safety metrics, audit instrumentation, assess confidence intervals and provide a rollback plan. None of these steps has been executed on customers.

## 4. Quality limitations

- 10 model-inference examples cannot support reliable significance or generalization.
- Prompt B's guidance and this manually composed dataset may have correlated wording.
- The rule-based specialists test orchestration, not autonomous multi-agent intelligence.
- Citation-ID validity is NOT evidence that an answer is semantically true.
- Basic regex prompt-injection filtering is NOT a robust jailbreak defense.
- There is no real banking data, no authenticated model operations, no production load test, and no verified customer benefit.
